## Plan: Navbar mobile — hamburger menu + dropdown (PWA)

### Mục tiêu
Trên mobile (`< sm`), thay hàng nav thứ 2 hiện đang render toàn bộ 5 nút ("Hóa đơn", "Thông báo", "Chi phí", "Tài xế", "Cài đặt" — kèm badge chưa đọc) bằng một **nút hamburger icon** ở header; bấm vào mở **dropdown menu** chứa các mục nav.

### Thay đổi — chỉ 1 file: `components/dashboard-shell.tsx`

1. **Thêm `"use client"`** ở đầu file (component cần `useState` để quản lý trạng thái mở/đóng menu; props `user`/`nav` truyền từ layout server component vẫn hoạt động bình thường — chỉ là dữ liệu serializable).

2. **Xóa hàng nav mobile hiện tại** (`<nav className="... sm:hidden">` render thẳng các Link).

3. **Thêm nút hamburger** vào cụm bên phải header (`ml-auto` cluster, cạnh `ProductTour` + `SignOutButton`), chỉ hiện trên mobile (`sm:hidden`):
   - Icon `Menu` từ lucide-react, đổi thành `X` khi đang mở
   - `aria-label="Mở menu"`, `aria-expanded` đúng trạng thái

4. **Dropdown menu** render khi mở (đặt trong `relative` wrapper, anchor bên phải):
   - Mỗi mục: `Link` tới `item.href` + label + **giữ nguyên `NavBadge`** (số thông báo chưa đọc) — tái sử dụng component `NavBadge` đã có
   - Bấm vào mục → đóng menu rồi điều hướng (`router` hoạt động qua Link bình thường)
   - **Lớp phủ mờ** (`fixed inset-0`) phía sau dropdown để bấm ra ngoài là đóng menu — đơn giản, không cần thêm thư viện
   - Style theo theme hiện có: `bg-sidebar`, `border-sidebar-border`, shadow, `rounded-xl`

5. **Giữ nguyên** nav desktop (`hidden sm:flex`) và badge chưa đọc — không đổi hành vi trên màn hình lớn.

Không cần component mới, không thêm dependency (không dùng dropdown-menu package — dropdown tự làm bằng state đơn giản, đúng scale app này).

### Kiểm chứng
- `npx tsc --noEmit` + `pnpm build` sạch
- Thủ công trên mobile (hoặc cửa sổ hẹp): chỉ thấy hamburger thay vì 5 nút; bấm mở menu thấy đủ 5 mục + badge; bấm mục → điều hướng + menu đóng; bấm ra ngoài → menu đóng; desktop không đổi
